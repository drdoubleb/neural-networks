    A foundation model, in miniature

    pretrained on 100 nuclei without a single label · reused later for every question

    So far every question trained its own network from scratch on labelled cases. A foundation model is pretrained once, on many unlabelled images, to turn any image into a short code; the questions come later, each with a few labelled cases on top of the code. Nothing here rebuilds the nucleus. The miniature encoder plays a game with no labels in it, spot the same nucleus: ① take a nucleus and make two views of it (a flip or rotation, or the other lab’s scan); ② the encoder turns each view into 8 numbers; ③ among all the other views in the batch, it must find the partner by comparing the numbers; ④ the weights are nudged so the partner scores higher next time. To win, the code has to keep what makes a nucleus itself (its outline, size, texture) and ignore what a view changes (orientation, stain), and that is exactly what the questions later need. The 100 nuclei come from all three questions; the network is never told which. Once it has pretrained, go to 2 · Train and choose the input the code: a single layer on these 8 numbers, with as few labelled cases as you like.

    The game: spot the same nucleus

    one view of the last batch (or of the nucleus you pick below) against every other view of the batch · no label anywhere

    The encoder turns every view into 8 numbers and compares them by cosine; the vote is a softmax over the cosines at temperature 0.2. The answer is the nucleus’s other view, framed in orange. At the start the vote is spread thin over every candidate; pretraining is nothing but making the partner win this game, for every view of every batch. Watch the orange bar grow as it runs.

    The encoder, live · one pair of views

    the nucleus of the last batch (or the one you click below) goes through the encoder · hover any filter, map or connection

    What the code learns to keep, and to ignore

    the same nucleus in all 8 orientations from both labs, and the code of each view · at the start and now · then another nucleus

    Each strip is one view’s code, the 8 numbers as bars on one scale per row. At the start a nucleus’s 16 codes are no closer to each other than to another nucleus’s: a random encoder gives every view much the same code, so nothing is told apart. Pretraining makes a nucleus’s own codes agree (orientation and stain are ignored) while a different nucleus’s codes move away (its identity is kept). Untick the other lab’s scans above, reset, and the right-hand half no longer lines up.

    This batch: 8 of its 20 nuclei, two views each

    every view against every other · ringed cells are the pairs

    Orange = alike, blue = unlike. Pretraining pulls the ringed cells towards orange and everything else towards blue: each nucleus becomes recognisable across its views and distinct from the rest. Views are flips, rotations and (when ticked) the other lab’s scans.

    Foundation: a code from 100 unlabelled nuclei

    the specimens of the foundation question · no labels anywhere

    100 nuclei from the three image questions’ training sets (34 from atypia, 33 from enlargement, 33 from irregularity), our lab’s scans, and never a label. The foundation model will learn to turn each of them into a code of eight numbers without being told what any question asks; afterwards a single layer on that code, trained with a handful of labelled cases, answers each question.     Chat

    The transcript

    From the next-word model to a chatbot, and to an agent

    what a real system does, and what this toy does of it

    1 · Pretraining

    The Reports question is pretraining in miniature: a pile of text and one task, the next word. A real model does the same over trillions of words of web pages, books and code, and that is where nearly everything it knows is learned. Nothing in that stage says the model should answer anyone.

    2 · Instruction tuning

    To make a chatbot, the same model trains the same way on a smaller corpus of transcripts: a system line, the user's turn, the assistant's turn, with the assistant's turns written the way one wants answers to read. The next word again, nothing else: the model learns that after ASSISTANT: comes an answer to what the user asked. This question is that stage, on 2,400 toy transcripts, except that it starts from random weights rather than from the report model, whose vocabulary is a different one.

    3 · Preference tuning

    A third stage makes the answers people prefer more likely: the model writes two answers, a person (or a model trained on people's choices) picks the better one, and the weights move towards it. That is where tone, refusals and much of the polish come from. Not done here: the page has no preferences to learn from.

    The system prompt

    You are the pathology assistant of the Example Hospital reporting system.
Answer the pathologist's questions about the case in front of them from the case's findings only, and say when a question cannot be answered from them.
Keep answers short unless the pathologist asks for the reasoning.
Never present a diagnosis as final: the pathologist signs out.
Tools: findings() returns the image analyser's findings for the open case. To call a tool, write its name on a line of its own; the result follows in a TOOL turn.

    A real chatbot runs with text like this placed before the conversation by the people who run it, often thousands of words of persona, rules, formats and tools, and the model continues from it as from anything else. The words work because the model met instructions like them, in countless phrasings, in instruction tuning. The toy's system line is one sentence, in three phrasings per style: enough for the model to learn each phrasing as a cue for a style of answer, which is the honest description of what it does. On the Test step, rephrase it and watch the cue fail.

    An agent

    An agent is the chatbot in a loop with a program. The model writes a tool call as text; the program sees it, runs the tool, pastes the result into the transcript as a TOOL turn and asks the model to continue; the model reads the result and writes the next step, or the answer. Nothing in the model changes: the agency is the loop. In the agent style here the user asks the question alone, the assistant writes findings(), the page runs it, pastes the analyser's findings for the case, and the assistant answers from them.

    What this toy cannot do

    Its vocabulary is 133 words, all from these transcripts. It has never read an instruction, only met these; a question it was never asked gets a fluent answer, right or wrong, because the next word is all it knows how to write; findings() is three tokens it learned to write after one kind of system line, not a function it knows. A real model is the same machine with far more words, far more text and the two later stages: better at all of this, and at that last thing too.

      Measurements

      Nucleus Net is a teaching toy: a small network with hand-written backpropagation — optional convolution, up to two dense hidden layers — trained in your browser on synthetic blood counts and nuclei. Keys: 1 2 3 switch steps, space trains or pauses, N classifies the next test case; during a walk-through space pauses and ← → step. Every nucleus comes as two scans, ours and another lab’s with a weaker stain, for the lab-difference and shortcut-learning points; every question has the same three steps, specimens, train and test; the foundation question pretrains a miniature foundation model on 100 nuclei without labels, the slides questions train attention over slides of twenty nuclei with one label each, with one layer of self-attention on the way, and the reports question trains a small language model that writes a biopsy report from an analyser's findings. Regenerate the cases with node tools/generate_cbc.js and node tools/generate_nuclei.js.
